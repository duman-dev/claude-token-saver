## 1 — Лаконичные запросы

Стиль Claude по умолчанию — разговорный. Каждое вступление, резюме и "Я рад помочь" обходится в токены вывода — и перечитывается в будущих поворотах как часть истории.

**Решение:** Вставь это в `CLAUDE.md` (Claude Code) или **Настройки → Профиль → Пользовательские предпочтения** (claude.ai):

```
Reply in the language user employs. Use most concise form possible.
Skip pleasantries, preambles, recaps.
No "I'd be happy to", "Great question", "Let me explain".
Drop articles, filler words wherever meaning stays clear.
Prefer short declarative sentences. If tool call needed,
run first and show only result. Do not narrate steps.
Prioritize code/data format over prose.
No explanations unless essential. Output only.
```

**Было:**
> "Отличный вопрос! Я рад помочь тебе. Чтобы исправить эту ошибку, нужно проверить нулевую ссылку на строке 12. Позволь мне объяснить, что здесь происходит..."

**Стало:**
> "Нулевая ссылка на строке 12."

Одинаковый ответ. Минимум токенов.

## 2 — Редактирование вместо переписки

Когда Claude не понял суть, рефлекс — отправить исправление: *"Нет, я имел в виду..."* Это исправление добавляется в историю. Неправильный ответ остаётся. Оба перечитываются в каждом следующем ходе.

**Решение:** Отредактируй исходное сообщение и перегенерируй вместо ответа.

| ❌ Переписка | ✅ Редактирование |
|---|---|
| Исходное сообщение остаётся | Исходное сообщение обновляется |
| Неправильный ответ в истории | Неправильный ответ удаляется |
| Оба перечитываются каждый ход | Только правильный диалог в контексте |

В Claude Code: когда сеанс сбился, начни новый сеанс вместо попыток вернуть старый.

---

## 3 — Компрессия контекста

Каждое сообщение несёт полную историю разговора. После 15–20 сообщений большая часть этой истории нерелевантна — но всё равно загружается каждый ход.

**Решение:** Перед началом нового чата отправь этот запрос для оптимизированной передачи:

```
Summarize our entire conversation with language user employs
so I can paste it into a
new chat and continue without losing context. Include:
(1) the original goal or problem
(2) key decisions made and why
(3) any code, config, or data we settled on, verbatim, in code blocks
(4) open questions and next steps
Use short sections with headings. Skip small talk and
exploratory tangents. Optimize the summary for a future
Claude reading it cold.
```

Вставь результат первым сообщением нового чата. Сеанс из 40 сообщений превратится в 200-словное резюме — история не тащится за собой.

---

## 4 — Пакетная обработка вместо разделения

Каждое сообщение перезагружает полную историю разговора. Три маленькие задачи отправлены отдельно = три загрузки истории. Все три вместе = одна загрузка.

**Решение:** Объедини связанные запросы в одно сообщение.

**Было:**
```
Ты: Исправь опечатку в этой функции
Ты: Теперь добавь документацию
Ты: И добавь type hints
```

**Стало:**
```
Ты: Исправь опечатку, добавь документацию и type hints
```

Побочный эффект: результаты более согласованные, потому что Claude видит полную картину сразу.

## 5 — Оптимизация токенов с помощью скиллов вроде Caveman

Методы выше сокращают потери токенов за счёт *того, как ты* используешь Claude. Специализированный скилл может дополнительно сжимать *то, что отправляется* — с обеих сторон разговора.

[**Caveman**](https://github.com/juliusbrussee/caveman) — это open-source скилл/плагин, который сжимает вывод агента (более краткие, "в стиле пещерного человека" ответы — заявленное сокращение до ~87% на некоторых задачах), а через опциональный локальный прокси также сжимает ввод до того, как он достигнет модели (JSON, логи, code diff и длинные тексты урезаются до сути, оригиналы при необходимости восстановимы локально).

**Решение:** Установи скилл и включай его по мере необходимости в сессии.

```bash
curl -fsSL https://raw.githubusercontent.com/JuliusBrussee/caveman/v1.10.0/install.sh | bash
```

Затем в Claude Code:

```
/caveman [lite|full|ultra|off]
```

Экономия зависит от нагрузки — воспринимай бенчмарки проекта как отправную точку, а не гарантию, и сравнивай их со своей базовой линией перед тем, как полагаться на них в задачах, критичных к задержке или стоимости.
